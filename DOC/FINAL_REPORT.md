**Дата:** 17 марта 2026  
**Статус:** 🟢 В активной разработке

---

## 1. Резюме

Проект успешно прошёл этап декомпозиции монолитного API: backend теперь организован в доменные роуты и централизованный роут-агрегатор. Текущий этап сместился с «создать базовый API» на «стабилизировать архитектуру и убрать технический долг перед слоистой моделью».

---

## 2. Фактические достижения

- API разделён на доменные роуты (`users/resources/bookings/payments/roles/logs`)
- Есть единый вход через `app.use('/api', indexRouter)`
- Админка на Vanilla JS покрывает основные CRUD-сценарии
- В бронированиях добавлена проверка конфликтов интервалов при создании
- Базовая JWT-аутентификация работает

---

## 3. Технический долг (актуальные блокеры)

1. `auth.routes.js` не интегрирован корректно в общий роутинг
2. Повторное подключение `errorHandler`
3. Несогласованный error-flow в роутах (`throw` и `next` одновременно)
4. Проверка конфликтов бронирования пока не доведена для `PATCH`
5. Архитектурные слои `controllers/services/repositories` ещё не внедрены
