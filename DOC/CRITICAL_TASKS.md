## [x] TASK 1: Починить auth-маршруты (1-2 часа)

**Проблема:** `auth.routes.js` не работает как полноценный router и не подключён в агрегатор.

**Что сделать:**
- Сделать `const router = express.Router()`
- Реализовать `POST /login`
- Подключить `router.use('/auth', authRoutes)` в `routes/index.js`
- Убрать дубли логики логина из других мест

**Результат:** единая точка аутентификации `/api/auth/login`

## [x] TASK 2: Нормализовать обработку ошибок (2-3 часа)

**Проблема:** в нескольких маршрутах есть смешанный стиль `next(error)` и `throw new ApiError(...)` в одном `catch`.

**Что сделать:**
- В `catch` использовать только `return next(error)` или `return next(new ApiError(...))`
- Удалить недостижимый код после `throw`
- Пройти все route-файлы и привести к одному стилю

**Результат:** предсказуемые ответы ошибок 400/401/403/404/500

---

## [x] TASK 3: Убрать двойное подключение errorHandler (30 мин)

**Проблема:** `errorHandler` подключается и в `api.js`, и в `server.js`.

**Что сделать:**
- Оставить `app.use(errorHandler)` только в одном месте (рекомендуется `api.js`)
- Удалить дублирующий вызов из `server.js`

**Результат:** ошибки обрабатываются один раз, без повторных ответов

## [x] TASK 4: Довести booking-конфликты до целостного поведения (1-2 часа)

**Сейчас:** в `POST /api/bookings` уже есть проверка пересечения интервалов.

**Что сделать:**
- Добавить такую же проверку в `PATCH /api/bookings/:id`
- Исключать текущую запись при редактировании
- Разрешить только контролируемые статусы (`pending/confirmed/cancelled`)

**Результат:** нет двойных бронирований ресурса на пересекающееся время

## TASK 5: Вынести role-check в middleware (1-2 часа)

**Проблема:** проверки роли повторяются SQL-запросами в разных роутах.

**Что сделать:**
- Создать middleware `requireRole([3])`
- Использовать `req.user.role_id` из JWT
- Подключить на `DELETE/PATCH` админ-операциях

**Результат:** меньше дублирования и консистентная RBAC-модель
