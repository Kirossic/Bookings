## 💡 ЧТО МОЖНО УЛУЧШИТЬ (Обучающие моменты)

### 1. Безопасность (учебные ошибки)

#### Проблема 1: Hardcoded значения по умолчанию
```javascript
// ❌ Текущий код
const JWT_SECRET = process.env.JWT_SECRET || '789456123';
```

**Почему это важно**: Если забыть установить .env, приложение будет использовать известный секрет.

**Как исправить** (учебный пример):
```javascript
// ✅ Лучше
if (!process.env.JWT_SECRET) {
    throw new Error('JWT_SECRET must be set in .env file!');
}
const JWT_SECRET = process.env.JWT_SECRET;
```

**Что вы узнаете**: Fail-fast принцип - лучше упасть сразу, чем работать небезопасно.

---

#### Проблема 2: SQL Injection в названиях таблиц
```javascript
// ⚠️ Текущий код
async function buildRead(table, id) {
    const query = `SELECT * FROM ${table} WHERE id = $1`;  // table не защищена
}
```

**Почему это важно**: Хотя вы защитили значения ($1, $2), названия таблиц тоже нужно защищать.

**Как исправить** (учебный пример):
```javascript
// ✅ Вариант 1: Whitelist
const ALLOWED_TABLES = ['users', 'resources', 'bookings', 'payments', 'roles', 'logs'];

async function buildRead(table, id) {
    if (!ALLOWED_TABLES.includes(table)) {
        throw new Error(`Invalid table: ${table}`);
    }
    const query = `SELECT * FROM ${table} WHERE id = $1`;
    return await con.query(query, [id]);
}

// ✅ Вариант 2: Использовать pg-format
const format = require('pg-format');
const query = format('SELECT * FROM %I WHERE id = $1', table);
```

**Что вы узнаете**: Разница между защиты значений ($1) и идентификаторов (названия таблиц).

### 2. Архитектура (паттерны для роста)

#### Следующий шаг: Разделение на слои

**Текущий подход** (работает, но может быть лучше):
```javascript
// Все в одном месте
app.post('/api/users', validateRegister, async (req, res, next) => {
    // Валидация
    if (!name || !email) { return res.status(400)... }
    
    // Проверка дубликатов
    const check = await con.query('SELECT...');
    
    // Хеширование
    const hashed = await hashPassword(password);
    
    // Сохранение
    const result = await con.query('INSERT...');
    
    res.status(201).json(result.rows[0]);
});
```

**Следующий уровень** (профессиональный подход):
```javascript
// 1. Controller (обрабатывает HTTP)
class UserController {
    async create(req, res, next) {
        try {
            const user = await userService.createUser(req.body);
            res.status(201).json(user);
        } catch (error) {
            next(error);
        }
    }
}

// 2. Service (бизнес-логика)
class UserService {
    async createUser(userData) {
        // Проверка дубликатов
        if (await this.userRepo.findByEmail(userData.email)) {
            throw new ApiError(409, 'Email already exists');
        }
        
        // Хеширование
        const passwordHash = await hashPassword(userData.password);
        
        // Создание
        return await this.userRepo.create({
            ...userData,
            passwordHash
        });
    }
}

// 3. Repository (работа с БД)
class UserRepository {
    async create(userData) {
        const result = await db.query(
            'INSERT INTO users (name, email, password_hash) VALUES ($1, $2, $3) RETURNING *',
            [userData.name, userData.email, userData.passwordHash]
        );
        return result.rows[0];
    }
    
    async findByEmail(email) {
        const result = await db.query('SELECT * FROM users WHERE email = $1', [email]);
        return result.rows[0];
    }
}
```

**Преимущества**:
- ✅ Каждый класс делает одну вещь
- ✅ Легко тестировать каждую часть
- ✅ Можно переиспользовать логику
- ✅ Проще понять, что происходит

**Что вы узнаете**: Separation of Concerns, SOLID принципы

### 3. Оптимизация (производительность)

#### Учебный момент: Индексы базы данных

**Текущий код** (работает, но медленно):
```sql
-- Без индексов

**Как улучшить**:

```

**Что вы узнаете**: Как база данных работает "под капотом".

#### Учебный момент: Connection Pool

**Текущий код**:
```javascript
const {Client} = require('pg');
const con = new Client({...});
```

**Проблема**: Только одно соединение на всё приложение.

**Как улучшить**:
```javascript
const {Pool} = require('pg');
const pool = new Pool({
    max: 20,  // До 20 параллельных запросов
    min: 2,
});
```

**Что вы узнаете**: Как работает connection pooling и почему это важно.

### 4. Тестирование (следующий навык для освоения)

**Почему это важно**: Тесты помогают не сломать код при изменениях.

**Пример для начала**:
```javascript
// tests/api/users.test.js
const request = require('supertest');
const app = require('../../api');

describe('POST /api/users', () => {
    it('should create a new user', async () => {
        const response = await request(app)
            .post('/api/users')
            .send({
                name: 'Test User',
                email: 'test@example.com',
                password: 'password123'
            })
            .expect(201);
        
        expect(response.body).toHaveProperty('id');
        expect(response.body.email).toBe('test@example.com');
    });
    
    it('should reject duplicate email', async () => {
        // Создать первого пользователя
        await createUser({ email: 'test@example.com' });
        
        // Попытаться создать дубликат
        await request(app)
            .post('/api/users')
            .send({
                name: 'Another User',
                email: 'test@example.com',  // Тот же email
                password: 'password123'
            })
            .expect(409);  // Conflict
    });
});
```

**Что вы узнаете**: Test-Driven Development (TDD), Jest, Supertest.
