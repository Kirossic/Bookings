### 4. Система триггеров PostgreSQL

Добавлен файл `db/trigger.js` с PostgreSQL-триггерами:

```javascript
// Автоматическое логирование операций с пользователями
CREATE OR REPLACE FUNCTION log_user()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        INSERT INTO logs (user_id, action, details, created_at)
        VALUES (NULL, 'DELETE', 'User deleted. user_id=' || OLD.id, NOW());
    ...
END;
$$ LANGUAGE plpgsql;
```

Аналогичный триггер создан для таблицы `bookings`.

**Оценка**: ✅ Отличное решение. Автоматическое логирование на уровне БД надёжнее, чем ручное логирование в коде.

### 6. Улучшения обработки ошибок

В части маршрутов устранён паттерн недостижимого кода:


**СТАЛО** (в некоторых роутах):

```javascript
} catch (error) {
```

**Важно**: Паттерн НЕ устранён полностью. В нескольких местах до сих пор встречается:

```javascript
// resource.routes.js, log.routes.js, payment.routes.js, role.routes.js
```

## 🔴 НЕРЕШЁННЫЕ КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. Hardcoded JWT Secret
```javascript
// backend/src/api.js — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
process.env.JWT_SECRET || '789456123'
```
**Риск**: Критический. Если `JWT_SECRET` не задан в окружении, токены подписываются слабым известным ключом.

### 2. Hardcoded пароль БД
```javascript
// db/db.js — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
password: process.env.DB_PASSWORD || "12345678"
```
**Риск**: Критический. Слабый дефолтный пароль при незаданной переменной окружения.

### 3. SQL Injection через имена таблиц
```javascript
// backend/apiConstructor.js — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
const query = `SELECT * FROM ${table} WHERE id = $1`;  // table не экранируется!
```
**Риск**: Критический. Хотя таблицы сейчас передаются из доверенного кода, это архитектурная уязвимость.

### 4. Single Client вместо Pool
```javascript
// db/db.js — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
const con = new Client({...});
```
**Риск**: Средний. Одно соединение с БД — узкое место производительности.

### 5. Автоудаление дублей при каждом подключении
```javascript
// db/db.js — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
con.connect().then(() => {
    // Удаляет записи при КАЖДОМ старте сервера
    con.query(`DELETE FROM bookings WHERE id NOT IN (...)`)
```
**Риск**: Средний. Деструктивная операция при каждом подключении к БД.

### 6. SELECT * в запросах
```javascript
// Везде — СТАТУС: ❌ НЕ ИСПРАВЛЕНО
con.query('SELECT * FROM bookings')
```
**Риск**: Низкий. Передача лишних данных, утечка полей `password_hash`.

## 🟡 НОВЫЕ ПРОБЛЕМЫ (выявленные в текущем коде)

### 1. Дублирование маршрутов в resource.routes.js
```javascript
// resource.routes.js — ДВА обработчика PATCH /:id
router.patch('/:id', verifyToken, validateResource, ...)  // строка ~15 (только status)
...
router.patch('/:id', verifyToken, validateResource, ...)  // строка ~55 (все поля через buildUpdate)
```
**Проблема**: Express выполнит только первый совпадающий маршрут. Второй `PATCH /:id` недостижим.

### 2. Лишний SQL-запрос при проверке роли
```javascript
// Во всех DELETE-роутах
const user = await con.query('SELECT role_id FROM users WHERE id = $1', [req.user.id]);
// req.user.role_id уже содержит эту информацию из JWT
```
**Оценка**: Лишний запрос к БД. Можно использовать `req.user.role_id` напрямую.

### 3. Непоследовательная обработка ошибок
В одних роутах используется `next(error)`, в других — `throw new ApiError(...)` без `next`:
```javascript
// booking.routes.js GET /
router.get('/', verifyToken, async (req, res) => {  // Нет параметра next
    throw new ApiError(500, 'Ошибка сервера');  // Не будет поймана errorHandler
```
Async-обработчики без `next` не передают ошибки в `errorHandler`.

### 4. auth.routes.js — закомментированный файл
```javascript
// routes/index.js
// const authRoutes = require('./auth.routes.js');
// router.use('/auth', authRoutes);
```
Файл `auth.routes.js` создан, но не подключён. Регистрация пользователей находится в `user.routes.js`, что сбивает с толку.

### 5. server.js — неиспользуемые импорты
```javascript
// backend/src/server.js
const { hashPassword } = require('../hashing.js');
const verifyToken = require('../verifyToken.js');
const { validateRegister, validateResource, validateBooking } = require('../../middleware/validators.js');
```
Эти импорты не используются в `server.js` — наследие от старой монолитной структуры.
